# CLAUDE.md — инструкции для AI-агентов

Этот документ описывает правила работы с репозиторием для AI-агентов (Claude Code и других).

## О проекте

Учебный репозиторий курса «Программирование на Python» для студентов МФТИ (1 семестр, осень 2026):

- **Модуль 1: Основы программирования на Python** (семинары 1–11) — от базовых конструкций
  языка до ООП, работы с сетью и контроля качества кода.

Курс вводный: студенты начинают с нуля. Материалы опираются на **стандартную библиотеку**
Python; внешние библиотеки появляются только начиная с семинара 9.

**Версия Python:** 3.10 или выше (в репозитории зафиксирована 3.12 в `.python-version`).

## Настройка окружения

Проект использует **uv** для управления зависимостями.

```bash
# Установить uv (если не установлен)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Создать виртуальное окружение и установить зависимости
uv sync --all-extras

# Активировать виртуальное окружение
source .venv/bin/activate  # Linux/Mac
.venv\Scripts\activate     # Windows

# Добавить зависимость
uv add <package-name>

# Добавить dev-зависимость
uv add --dev <package-name>
```

## Команды проверки и запуска

### Форматирование и линтинг (Ruff)

```bash
uv run ruff format .                 # Форматирование
uv run ruff format path/to/file.py

uv run ruff check .                  # Проверка
uv run ruff check --fix .            # Автоисправление

uv run ruff check --fix . && uv run ruff format .
```

### Проверка типов (ty)

```bash
uv run ty check
uv run ty check path/to/file.py
```

### Тесты (pytest)

```bash
uv run pytest                                          # Все тесты
uv run pytest -v                                       # Подробный вывод
uv run pytest --cov=seminars --cov-report=html         # С покрытием
uv run pytest path/to/test_file.py                     # Один файл
uv run pytest path/to/test_file.py::test_function_name # Один тест
uv run pytest -k "pattern"                             # По шаблону имени
```

### Запуск примеров

```bash
uv run python seminars/seminar_01_intro_to_python/examples/01_hello_world.py
```

## Стиль кода

### Общие правила

- Следовать PEP 8
- Форматировать через Ruff (длина строки: 88)
- Использовать аннотации типов в сигнатурах функций
- Проверять типы через ty

> **Важно:** курс вводный. В ранних семинарах (1–4) примеры должны оставаться простыми:
> без «продвинутых» конструкций, которые ещё не проходились. Аннотации типов и
> `if __name__ == "__main__"` вводятся постепенно и объясняются при первом появлении.

### Импорты (сортируются ruff)

```python
# Стандартная библиотека
import socket
from pathlib import Path

# Сторонние библиотеки
import requests

# Локальные модули
from .models import User
```

### Докстринги

```python
"""Описание модуля."""


def function_name(param1: str, param2: int) -> bool:
    """Краткое описание.

    Args:
        param1: описание param1
        param2: описание param2

    Returns:
        Описание возвращаемого значения
    """
```

### Соглашения об именовании

| Сущность | Соглашение | Пример |
|----------|------------|--------|
| Переменные | snake_case | `user_name`, `order_id` |
| Функции | snake_case | `get_user()`, `create_order()` |
| Классы | PascalCase | `MenuItem`, `OrderItem` |
| Константы | UPPER_SNAKE | `MAX_ITEMS`, `DB_PATH` |
| Приватное | _underscore | `_internal()`, `_cache` |

### Аннотации типов

```python
def get_order(order_id: int) -> dict | None:
    """Получить заказ по ID."""


def process_items(items: list[str], limit: int = 10) -> dict[str, int]:
    """Обработать элементы и вернуть счётчики."""
```

### Обработка ошибок

```python
try:
    value = int(user_input)
except ValueError:
    print("Введите целое число")
    raise
```

### Организация файлов

```python
# У каждого запускаемого скрипта должно быть:
if __name__ == "__main__":
    main()
```

## Тесты

- Тесты лежат рядом с кодом и называются `test_*.py`
- Имена тестов описательные: `test_create_order_with_valid_items`
- Для подготовки данных использовать фикстуры
- Проверять и успешный сценарий, и ошибочный

```python
def test_function_returns_expected():
    result = function_under_test(input_value)
    assert result == expected
```

## Структура семинара

Все семинары строятся по принципу **«теория → сразу практика»**. Вместо большого блока
теории и большого блока задач семинар разбит на небольшие тематические блоки: после
каждого блока теории (с примерами) студенты переходят к упражнениям именно по этой теме.

### Структура директории семинара

```
seminar_XX_topic_name/
├── README.md                # Основной документ семинара (блоки теории со ссылками на практику)
├── data/                    # Данные и вспомогательные файлы (где применимо)
├── examples/                # Примеры кода по блокам теории
│   └── NN_topic.py
└── exercises/               # Документ с упражнениями
    └── *.md
```

### Структура README.md семинара

1. **Заголовок** — название семинара, модуль, дата и время, ссылка на презентацию
2. **Цели семинара** — список того, что студент сможет после занятия
3. **Подготовка** — что установить/скачать, как запускать примеры
4. **План семинара** — таблица с таймингом, блоками и ссылками на разделы упражнений
5. **Блоки теории** — каждый блок содержит:
   - короткое объяснение с примерами кода
   - ссылку на подробные примеры: `> **Подробнее:** см. файл [examples/...](examples/...)`
   - раздел `### Практика` со ссылкой на нужный раздел упражнений
6. **Файлы семинара** — таблица со ссылками на файлы директории
7. **Дополнительные материалы** — внешние ссылки для углублённого изучения

### Структура файла упражнений

1. **Подготовка** — как подготовить окружение
2. **Инструкция** — напоминание сначала решить самостоятельно, потом смотреть решение
3. **Части** — по одной части на блок теории, в каждой:
   - ссылка назад на блок теории и файл примеров
   - несколько задач по возрастанию сложности
   - `<details><summary>Подсказка</summary>` для каждой задачи (по желанию)
   - `<details><summary>Решение</summary>` с решением
4. **Дополнительные задания** — сложные задачи, объединяющие несколько тем

### Ключевые принципы

- **Маленькие порции**: теория → практика → теория → практика
- **Самостоятельность**: студент сначала пробует решить сам, потом раскрывает решение
- **Перекрёстные ссылки**: упражнения ссылаются на блок теории и наоборот
- **Подсказка перед решением**: подсказка направляет, но не выдаёт ответ
- **Нарастающая сложность**: задачи внутри части идут от простых к сложным
- **Бонусный раздел**: задачи для тех, кто справился быстрее
- **Тайминг**: длительность семинара — 90 минут (18:40–20:10); в плане закладывайте
  ~10 минут на переходы, вопросы и организационные моменты

## Язык

- **Основной язык репозитория — русский**: README, документы семинаров, упражнения,
  комментарии и докстринги пишутся на русском
- **Идентификаторы в коде** (переменные, функции, классы, имена файлов и директорий) —
  только на английском
- Сообщения коммитов — на английском

## Работа с материалами

- Не создавать материалы будущих семинаров заранее без явной просьбы: в подготовленных
  директориях лежат заготовки README с пометкой «Материалы в подготовке»
- При наполнении семинара заменять `_TODO_` реальным содержанием и убирать пометку
- Примеры кода должны быть запускаемыми и проверенными: перед сдачей прогонять
  `uv run ruff check --fix . && uv run ruff format .`
